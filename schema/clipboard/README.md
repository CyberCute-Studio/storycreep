# Clipboard

A clipboard is a selection of the nodes of one board of a project, as copied: the nodes, with a branch's outputs, the connections between them, and a declaration of each variable, component, and attribute definition that their texts, expressions, and speakers name (PRD FR-EDIT-07, plan note N58). `POST /api/v1/projects/{project_id}/clipboard/copy` answers with one, `POST /api/v1/projects/{project_id}/clipboard/resolve` reports what of one a paste onto a board would resolve to nothing, and the command `clipboard.paste` pastes one onto a board of the same project or of another of the workspace's. A client puts the clipboard on the system's clipboard as JSON, which its `format`, `storycreep.clipboard`, tells from other JSON.

## Versions

A clipboard names its version in `version`. A change of what a clipboard holds, as a new field of a node, is a new version, with a schema of its own at a path of its version, as the published format's `schemaVersion` is (PRD §6.4). A server reads every version up to the one that it writes, and answers a newer one with 422 `validation_failed` at `clipboard.version`, which the schema of the version that it writes bounds, with whatever else of it that schema refuses, as a field that the newer version adds, so that a client that pastes a clipboard copied from a newer server learns why.

## What it holds

- The nodes, each once, in the order of their IDs, with every field of a node but its board, and its position, which a paste moves by its offset, so that the pasted nodes keep their places relative to each other. A branch holds its outputs in their order, its conditional outputs, the first its `if`, and its `else` after them.
- The connections that leave one of the nodes and enter one of them, in the order of the ports that they leave, by their nodes' IDs and then their outputs' IDs, an element's `out` first, and of each port's choices, which a paste keeps.
- A declaration of each variable, component, and attribute definition, not in the trash, that the nodes' and the connections' texts name by value references and mentions, that their expressions' names name at the clipboard's board, and that the elements' speakers are, as it was where it was copied: what a paste resolves it by, its ID, its key, and its scope, and what creating one in its place takes, as a variable's type, default, and description, and an attribute definition's name and default. A paste holds a declaration, which it does not write, only to what reading it takes, so that a clipboard of what a project holds that a rule has changed for since pastes all the same, though creating one in its place may be refused.

IDs are the IDs where the clipboard was copied. A paste gives every node, output, and connection a new ID, which the client makes, as it makes those of what it creates.

A copy is refused where its clipboard would pass the bounds that the schema says, as 10,000 connections, or 4 MiB of JSON with the new IDs that a paste of it gives, so that a paste of it fits in a request's body of 5 MiB, with a mebibyte for the rest of its batch: the commands that create what the report lists, which a client sends in batches before the paste's where they do not fit with it.

## How a paste resolves what the content names

A paste resolves each declaration at the board that it pastes onto:

- A variable resolves to the same variable, where the board reaches it, a global one or one of the board, and else to the variable of its key and scope: a global one, or one of the board. So a board's variable never resolves to a global one, nor a global one to a board's.
- A component resolves to the same component, and else to the one of its key.
- An attribute definition of a component that resolves resolves to the same definition, where it is of the type of the component that it resolves to, and else to the one of its key of that type, for each component that declares it apart, since the components of a type share its definitions, but may resolve to components of different types, or one to none.

None of them resolves to what is in the trash. What the content names that resolves is written as what it resolves to: a text's value reference or mention names its ID, and an expression's name is the shortest name that names it at the board, as a rename writes one (PRD FR-VAR-03), an attribute's with the key of the definition that it resolves to. What resolves to nothing is kept as it is in a text, which the validation then reports (FR-TEXT-02 AC2), and written explicitly in an expression, as `global.<key>`, `board.<key>`, or `cmp.<component>.<attribute>`, so that it names nothing of another scope or kind meanwhile, and names what a later variable or component of its key is once one is created. `<key>.<attribute>` whose key names a variable where the clipboard was copied, which has no attribute, so that the validation reports the name, names that variable, which the clipboard declares: it is written with the key of the variable that it resolves to, so that it names no component of its key, and stays as it is where that resolves to nothing, as no name names a variable's attribute explicitly, so that it names the attribute of a component of its key where the project has one, and no variable of the key, until the variable that the report lists is created. A speaker that resolves to nothing, or that the clipboard does not declare, as one in the trash where it was copied, is kept where the board's project has it, in its trash or not, as a text's reference is, and a speaker, a jumper's target outside the clipboard, and a cover image that the board's project does not have are left out, each of which the report lists. A jumper's target that is one of the clipboard's nodes is that node's copy, and so is what an expression's node reference to one names. An expression's name keeps the white space and the comments between its parts, as a rename keeps them, and so a variable's qualifier, `global.` or `board.`, that a comment follows, which is written as the one of the scope of the variable that the name resolves to, as a variable whose scope has changed since the copy is of the other. A source that does not parse names nothing, and is pasted as it is, as a rename leaves one.

The report lists each of what resolves to nothing once for what a client creates in its place: a variable once for its key and scope, as the clipboard may declare variables of one key of several boards, which a text names, and which each resolve to the one of the board pasted onto, and an attribute definition once for the project's component type that lacks it, the type of the component that its component resolves to, or the one that the report gives a component that resolves to none, and its key, as the components of a type share its definitions. A component that resolves to none, of a type that the project lacks, is created with its type, and with each definition that the clipboard declares of it. A client that asks the report first, and creates what it lists in the batch of the paste, before it, or in batches before it where they do not fit in the paste's, has the paste resolve to what it created. A paste is refused at a source that the names that it writes, those of what resolves to nothing explicitly, would make longer than a source may be.
