# App shell paths

`paths.json` holds the paths under `/app/` that the server answers with the web app's entry page, the app's shell, in `entry`, and some that it answers otherwise, in `other`: with a redirect, with a file of the build, or with `not_found` (PRD FR-OFF-01, plan note N95). The server's pages (`server/internal/httpserver/pages.go`, `TestShellPaths`) and the app's service worker, which answers a navigation with the shell that it keeps when the server would answer it with the entry page (`web/app/src/sw/shell.ts`, `answersWithShell`), both run every path, so the two cannot drift apart.

The server answers a path under `/app/` with the entry page when, decoded, it is `/app/` itself, or a valid path of Go's `io/fs` (UTF-8, with no empty, `.`, or `..` segment, once one trailing slash is taken off) that is outside `assets/`, is not `index.html`, and whose last segment has no dot, as a file's extension would. The server's test serves a bundle of `index.html`, `favicon.svg`, `manifest.webmanifest`, `sw.js`, `icons/icon-192.png`, and `assets/index-abc.js`.

The paths are as a browser sends them: it resolves `.` and `..` segments, and their percent-encodings, before it asks, so neither side sees them, and they are not here. A query does not change the answer. A file of the build without an extension would be served as a file by the server but answered with the shell by the worker; the build has none.
